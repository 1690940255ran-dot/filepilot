## 5. 脚本自身的缺陷（交付给别人的东西，先自己当用户跑一遍）

把验收脚本交给对方之前，我按**对方的用法**（别的目录、绝对路径、连跑、非预期环境）
跑了一遍，抓到四个真问题：

| # | 现象 | 根因 | 处置 |
|---|---|---|---|
| 1 | 报 `.\verify-clean-machine.ps1 不存在` | 命令在别的目录下敲，`.\` 指当前目录 | 说明里加 `cd` 与绝对路径两种写法；加 `run-env-check.cmd`（用 `%~dp0` 定位自身） |
| 2 | 卸载阶段拒绝执行 | 见到应用在运行就 `return`，而 install 阶段**故意**留着应用 | 改为先 `CloseMainWindow()` 优雅关闭（不强杀——强杀会跳过应用自己的收尾） |
| 3 | 跑完 `-Phase env` 后问「怎么没打开应用」 | `env` 是只读的，但**输出里没写清楚** | 加显式提示 + 操作步骤里的三阶段对照表 |
| 4 | 提示里文件名过期（`README-验收步骤.txt` → 实际叫 `操作步骤.txt`） | 改名后漏改引用 | 修正 |

另外补了 `-AllowDirty`（显式认领"平台探测"）与 `-Draft`（开发期试跑不污染正式报告）。

> **可复用结论**：交付给他人的脚本，必须按对方的用法跑一遍。
> 上面四个问题在"我自己习惯的用法"下**永远不会触发**。

## 8. 交接说明（给下一位接手的人）

**要做的第一件事**：弄一台干净的 Windows 11 x64。

- 本机是家庭版，**没有 Windows Sandbox，也没有 Hyper-V** → 只能用 VMware 等第三方虚拟机；
- 虚拟机内需临时关闭 TPM/安全启动检查才能装 Win11（家庭版装 Win11 的常见做法），
  具体步骤见 `docs/CLEAN_MACHINE_ACCEPTANCE.md` §0.0；
- 装完**不要**装任何开发工具 —— 那会让这台机器失去验收资格。

**第二件事**：照 `C:\fp-verify\操作步骤.txt` 走一遍。

- 先跑 `-Phase env` 确认三个前提行都是「满足 / 否」；
- 再跑 `-Phase install`（**不要**加 `-AllowDirty`，除非你明确只要冒烟）；
- 人工做 C / C2 / D / D2 / E / F 节；
- ~~**G 节务必做**~~ → **G 节已于 2026-09-25 由用户跑完**（见 §3.2.1），
  不必重跑；在干净 Win11 上顺手复验一次更好，但不再是缺口；
- 最后 `-Phase uninstall`，核对用户数据保留。

**第三件事**：把 `report.txt` 与截图交回，并把结果填进
`docs/CLEAN_MACHINE_ACCEPTANCE.md` 的结论表。

**别做的事**：为了让安装通过而关闭杀毒软件或 Defender。
如果非关不可才能装，那本身就是必须上报的缺陷。
