## 这是什么

用自然语言整理本地文件夹的桌面应用。规则模式完全离线；AI 模式支持本地
Ollama 或云端 API（自备密钥）。所有文件变更都经过「预览 → 确认 → 执行 → 可撤销」，
AI 只产生建议，不直接动文件。

## 新功能

| 能力 | 说明 |
|---|---|
| 根目录授权与扫描 | 只读元信息，跳过隐藏/系统文件、`.git`、`node_modules`、临时下载；上限 10,000 文件 / 深度 20，超限明确提示截断 |
| 规则模式（离线） | 按类型（文档/图片/音视频/压缩包/其他）或按修改月份分类，可改名 |
| AI 模式 | 本地提取内容摘要 → 预览待发送内容 → 授权 → 模型建议 → 严格校验 → 确定性计划 |
| 预览与一次性确认 | 逐项显示来源、目标、动作、依据；可取消勾选、可改目标；确认令牌 5 分钟有效且只能用一次 |
| 执行与日志 | 逐项重新核对文件身份（卷 + 文件 id + SHA-256），发现变化立即停止；结果可选取消 |
| 崩溃恢复 | 启动时核对上次未完成的操作，区分「已应用 / 未应用 / 需要人工核对」，不自动继续 |
| 撤销 | 逆序生成恢复计划，冲突项默认不选中，可只撤销无冲突子集；重复撤销幂等 |
| 云模型密钥 | 只存 Windows 凭据管理器，不进数据库与日志 |

## 本次构建修掉的一个发布阻断缺陷

**安装版打不开（整页白屏）。** 前端用 Ajv 在**运行时**编译 JSON Schema 做契约校验，
需要 `'unsafe-eval'`，而生产 CSP 是 `script-src 'self'` → 校验器编译抛 `EvalError`
→ 前端启动即崩。开发模式因为 `devCsp` 含 `'unsafe-eval'`，本地怎么跑都是好的，
所以这个缺陷**只在安装版出现**。

修法是**构建期预编译校验器**（Ajv standalone），而不是放宽 CSP——
后者等于为了一处便利把 XSS 的门开一条缝。
同时新增 `pnpm test:prod-csp`：用**生产构建产物 + 生产 CSP**起服务跑界面回归，
把「两层 CSP 的差异」这个藏身处锁住（已验证该用例在修复前会红）。

细节与证据链见 `docs/TEST_MATRIX.md` 8.8。

## 已知问题与限制

**发布层面的**

- 安装包**未签名**，Windows 会提示「未知发布者」。没有代码签名证书，
  请用下面的 SHA-256 校验来源。
- **没有自动更新**（首版）。
- 当前修复候选包尚未完成 Windows 11 x64 干净机器验收；旧包曾在 Windows 10 VMware 环境完成平台探测，不能替代新包验收。

**功能层面的**

- 大于 100 MiB 的文件标记为超限，不参与整理。
- 重启后旧根目录授权失效；需要通过原生选择器重新选择并核验同一目录，才能撤销旧历史。目录身份不一致时拒绝授权。
- 扫描型 PDF（无文本层）返回「不支持」，首版不做 PDF 页面 OCR。
- 图片 OCR 依赖 Windows 系统 OCR 与语言包；语言包缺失会明确提示。
- 首版只移动文件、不改内容；「仅改大小写」「互换两个文件路径」「只改扩展名」
  这三类操作被明确拒绝。
- **首版不提供「一键清理应用数据」的入口**：想清就自己删应用数据目录，
  **删掉之后操作历史与撤销记录会一并丢失且不可恢复**
  （规格要求清理必须由用户明确选择并提示恢复记录会丢失——我们选择不做这个入口）。
- 网络盘、同步目录、联接点指向授权根目录之外的情况会被拒绝或跳过。

**旧包真机验收发现的可用性问题**（2026-09-25，原始记录见 `docs/POST_RELEASE_TODO.md`）

- 这些问题已在当前源码中处理：执行时立即关闭确认框并显示进度；历史可展开逐文件记录，并支持进入时刷新与分页；问题列表和统计布局已调整。自动化与截图回归通过，新包的实际安装验收仍待补齐。
