# 干净机器验收协议（规格 T17）

**这份文档就是 T17 缺失的那张纸。** 它要在一台**没有 Node、没有 Rust、没有开发工具**
的 Windows 11 x64 上照着走一遍，把结果填进最后一节。

为什么必须单独做：`docs/TEST_MATRIX.md` 第 8 节证明的是「安装包**产出了**」，
不是「装完之后能用」。**开发机上的全绿与用户拿到的东西之间隔着打包、安装、
路径解析三层，而那三层没有任何自动化覆盖。**

> **已经在本机（有开发环境）验过的部分**，见 `docs/TEST_MATRIX.md` 8.8，这里用
> `[本机已验]` 标出来，但你**仍然要在干净机器上重做一遍**——
> 「本机能跑」正是当初安装版白屏时得到的错误结论。

---

## 0.0 没有第二台机器时，怎么弄一台验收机

**本机不能当验收机**：它有 Node、Rust、数据库客户端、完整的开发环境，
还有一堆开发期留下的注册表与缓存。「本机能跑」这件事本身没有证明力——
安装版白屏那次就是被这句话骗过去的（见 `docs/TEST_MATRIX.md` 8.8）。

按代价从低到高，四条路：

### A. 本机开一台干净虚机（**推荐**，唯一能完整覆盖的一条）

家庭版的限制先说清楚，免得白折腾：

| 方案 | 家庭版（本机是 `CoreCountrySpecific`，Windows 11 25H2 / 26200）可用？ |
|---|---|
| Windows Sandbox | ❌ 家庭版没有这个功能 |
| Hyper-V | ❌ 家庭版没有 |
| **VMware / VirtualBox 等第三方虚拟机** | ✅ 可用（不依赖 Hyper-V） |

本机现状（2026-09-24 实测）：**没有装任何虚拟机软件**——`VMnet1` / `VMnet8`
两块网卡是上一次 VMware 安装的残留，服务与安装目录都已经不在了。
磁盘：`C:` 可用 140 GB、`D:` 可用 62 GB，放一台虚机够用。

> 2026-09-25 更新：用户已打开一台 VMware **Win10** 虚拟机；可用于兼容性试跑，
> 但不能替代本协议要求的 Win11 x64 正式验收。当前预检状态见
> `outputs/T17预检记录.md`。

步骤：

1. 装 **VMware Workstation Pro**（个人使用免费）/ 或 VirtualBox；
2. 下 **Windows 11 官方 ISO**（约 6 GB）——安装时选「我没有产品密钥」，
   **未激活也能正常使用**，验收不需要激活；
3. 虚机配置建议（本机是 16 GB 单通道，别多给）：
   **内存 4 GB、2 vCPU、磁盘 64 GB 动态、关掉 3D 加速**；
4. 若卡在「这台电脑无法运行 Windows 11」（虚机没有 TPM）：
   在安装界面按 `Shift+F10` 打开命令行 → `regedit` →
   `HKLM\SYSTEM\Setup\LabConfig` 新建三个 DWORD 并设为 1：
   `BypassTPMCheck`、`BypassSecureBootCheck`、`BypassRAMCheck`；
5. 装完先确认它是**干净**的：`where node` / `where cargo` 都应当找不到。

时间预算：下载 15~30 分钟 + 装系统 30~45 分钟 + 跑这份协议 30 分钟 ≈ **2 小时**。

**为什么值得**：G 节那三条（WebView2 已装 / 缺失 / 断网）**只有换环境才能测**，
而它们恰好是安装体验里最容易翻车的地方。

### B. 借一台机器（零成本，最接近真实用户机）

学校机房、实验室机器、家里的旧电脑、室友的机器都行。要求就两条：
**Windows 11 x64**、**没装开发工具**。机房机器往往比虚机更接近真实——
它们带企业策略、第三方杀软、受限的网络。

### C. 云电脑按小时

国内有按小时租的 Windows 云桌面（无影、云电脑之类），几元到十几元一小时。
注意两点：镜像常**预装一堆东西**（不满足「干净」的定义），
而且性能是共享的——**别在里面测性能基线**。
另外：**云主机（Windows Server）不能替代**，它不是 Windows 11，
验不了 WebView2 缺失那类场景。

### D. 降级：本机新建一个标准用户账户（**只是临时验证**）

能覆盖与覆盖不了的，必须分清：

| 项 | 新用户账户能验吗 |
|---|---|
| 用户级安装（无需管理员）、UAC 行为 | ✅ |
| `%LOCALAPPDATA%` 与凭据管理器按用户隔离 | ✅ |
| 中文用户目录名、路径解析 | ✅（新建账户可以用中文名） |
| 标准用户（非管理员）能不能装、能不能用 | ✅ |
| 是否依赖 Node / Rust / 开发工具 | ❌ 同一台机器上它们还在 |
| WebView2 缺失 / 断网安装 | ❌ |
| 杀软 / Defender 真实交互 | ❌ |
| 真正的「第一次打开」 | ❌ 注册表与缓存有前一次安装的残留 |

> **它是"多验一点"，不是"T17 完成"。**
> 用它跑完的项，在第 9 节里标成「新用户账户验证过」，**不要**标成「干净机器通过」。

### 无论走哪条路：三条不许做

1. **不许关杀软/Defender** 来让安装通过——那样测的不是产品。
2. **不许在验收机装 Node/Rust**（除了 C 路那些本来就装了的云镜像）。
3. **不许把「本机装过一次」当成这台的验收**——换环境的意义就在这里。

### 附：能不能用 Windows 10 跑？

**规格 T17 写的是「Windows 11 x64」，所以 Win10 上的结果不能把这一格填成「通过」。**
但**值得跑**，而且有些事情只有 Win10 能测到：

| 项 | Win10 上会怎样 |
|---|---|
| T17 验收结论 | ❌ 不能算（规格要求 Win11）——记为「平台探测」 |
| 安装 / 启动 / 卸载 / 数据保留 / worker 同级 | ✅ 都能验，且这些与系统版本关系不大 |
| **WebView2 缺失**（G 节第 2 条） | ✅ **Win10 通常不自带 WebView2**，安装会真的走 `downloadBootstrapper` 分支——这一幕在 Win11 上几乎造不出来（系统自带） |
| 断网 + 缺 WebView2（G 节第 3 条） | ✅ 同理，Win10 上更好造 |
| 权限 / 中文路径 / 抗杀软 | ✅ 与版本无关，能验 |

前提与注意：

- Win10 需要 **1809（build 17763）或更新**——再老就没有 WebView2 的支持了；
- 我们**没有**在代码里做任何 Windows 版本门槛判断（已核查：源码里没有版本判断，
  也没有 Win11 专属 API）；应用清单里也**没有声明** `supportedOS`（Tauri 上游默认），
  意味着系统不会为它启用版本兼容性 shim——所以「Win10 上能不能跑」只能**实测**，不能推理；
- `README.md` 与发布说明目前写的是「**仅 Windows 11 x64**」。这是「我们测过什么」的口径，
  **不要**在 Win10 探测之后顺手把它改成「支持 Win10」——要改得先有 Win10 上
  走完规则/撤销/重启全流程的证据。

**记录方式**：在 `docs/TEST_MATRIX.md` 里单开一行「Windows 10 平台探测（不计入 T17）」，
结论照实写；T17 那一格在 Win11 机器跑完之前保持「未做」。

## 0. 准备

**先把自动化的部分交给脚本**（`scripts/verify-clean-machine.ps1`）。
它只用系统自带的 PowerShell（干净机器没有 Python / Node），分三段跑：

```powershell
# 1) 环境审计 + 校验哈希 + 静默安装 + 启动检查
powershell -ExecutionPolicy Bypass -File .\verify-clean-machine.ps1 -Phase install `
  -ExpectedSha256 <发布页上的哈希>

# 2) ……按本文件 C/D/E/F/G 节人工做（脚本判不了白屏与交互流程）……

# 3) 卸载 + 核对「程序移除、用户数据保留」
powershell -ExecutionPolicy Bypass -File .\verify-clean-machine.ps1 -Phase uninstall
```

脚本自动覆盖本文件里带 `[脚本]` 标记的那些项：**环境是否干净、A 哈希校验、
B 的安装结论与安装目录清单（含 worker 是否与主程序同级）、H 的卸载与数据保留**。
它**不覆盖** C/D/E/F/G——那些要人看、人点。

脚本的三条行为值得知道：

- **机器不干净时它拒绝安装**（避免"在开发机上装成功"被误当成验收）；
  只想冒烟试跑时加 `-AllowDirty`，报告里会标明「平台探测/冒烟，不计入 T17」。
- **卸载阶段会先正常关闭应用**（`CloseMainWindow`，不是强杀）——
  安装阶段结束时应用是故意留开着的，所以「装完直接卸」这条连跑路径必须能自己收尾。
- 报告里会判定 **T17 前提（Windows 11 x64）**、**T17 前提（无开发环境）**、
  **WebView2 缺失**三行；前提不满足时明确写"不计入 T17 验收"。

> 脚本输出 `report.txt` / `report.json`，连同截图一起留档。

| 项 | 值 |
|---|---|
| 被测安装包 | `FilePilot_0.1.0_x64-setup.exe`（3,029,911 字节） |
| 期望 SHA-256 | `3e1ecb686fc740d212642c38125960fb955d4a75ff9487d32bb12dc1061ee8b0` |
| 机器 | Windows 11 x64，**无** Node / Rust / 开发工具 |
| 测试目录 | 自己造一个可以随便试的目录，**不要用真实资料** |
| 网络 | 前半程**联网**（WebView2 引导需要）；G 节再单独断网测 |

> 哈希与体积**只对你手上这一份文件有效**：本项目不宣称可复现构建
> （见 `docs/TEST_MATRIX.md` 8.7）。如果你要验收的是别处拿到的安装包，
> 请以发布页上写的那一组数字为准，而不是这份文档里的。

要留的证据：每节的截图或文字输出。第 9 节逐项填「通过 / 不通过 / 未测」。

## C. 规则模式全流程（核心）

造一个测试目录，放 8~10 个不同扩展名的文件（含中文名、含一个深层子目录）。

- [ ] 首页能选目录、能扫描
- [ ] 扫描结果里的「可整理 / 已跳过」数量与目录内容对得上
- [ ] 生成建议 → 预览表格里每一项都有「来源 → 目标 + 理由」
- [ ] 点「校验并获取确认」→「确认并执行」→ 执行完成
- [ ] **结果页的「已移动」数量与磁盘实际一致**
- [ ] 打开资源管理器，确认文件确实在目标分类目录里、内容没变

> 这一节是唯一能证明「安装版真的动了文件」的地方。

### C2. 大批量目录的即时反馈（2026-09-25 补录，2026-09-24 已修）

**来源**：用户在 T17 过程中报告「点确认执行没有反应」，

      **「已整理 N / M」**
- [ ] 记录实际表现：`________________________________`
- [ ] 执行期间**不要**强杀进程，观察最终是否正常完成

> 修复前的判定口径是三选一（任一条满足即可）；**修复后要求三条同时满足** ——
> 只满足其中一条仍会让用户产生「是不是卡住了」的疑问。
> 若三条全不满足 → 记为 P1 可用性缺陷（用户会误判为卡死，诱发强杀进程），
> **不阻断发布，但必须写入发布说明的已知问题。**

## E. 退出与重启的语义

- [ ] D 节完成后，在测试目录再加入一个新文件并整理一次，保留这次操作供重启测试
- [ ] 退出应用再启动：历史仍可查；直接撤销上一次会话的操作应提示重新授权根目录
- [ ] 原生选择器重新选择**同一个目录**，核验卷与目录文件身份后，旧操作应允许撤销且文件回原位
- [ ] 若同一路径已被另一个目录替换，身份不匹配时不能重授权旧操作
- [ ] 重启时若有未完成的执行：出现恢复提示，区分「已应用 / 未应用 / 需人工核对」，
      **不自动继续**

| 已装 WebView2 的机器 | ✅ 通过 | 宿主机与虚拟机两条记录一致：安装过程未额外下载，装完即可运行 |
| 移除 WebView2 的机器 | ✅ 通过（**能引导安装**） | 见下方「口径说明」 |
| **断网** + 缺 WebView2 | ✅ 通过（**给出了可理解的失败提示**） | 未静默装出一个打不开的程序 |

> **口径说明（必须一起读）**：G 节三条与「机器是不是干净」**正交**——
> 它验的是 `downloadBootstrapper` 这条分支的行为，与验收机的 Windows 版本、
> 有没有装 Node/Rust 都无关。用户正是在那台 VMware 虚拟机上完成的三条。
>
> 因此 G 节的结论可以被采纳，但它**不能**让 T17 那一格变成「通过」：
> T17 的硬前提（Windows 11 x64 + 无开发工具）仍然没有满足。
> **G 通过 ≠ T17 通过**，这两件事不要合并。
